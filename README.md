# 電波スコープ (denpa-scope)

Mac が受け取っている Wi-Fi の電波を、アナログメーターの針・オシロスコープ風の波形・周波数スペクトラムで見るツール。

- **メーター**: RSSI（受信強度 dBm）を、ばね＋ダンパで動く針で表示。直近10秒の最大/最小マーカー付き
- **波形**: 0.1 秒ごとの RSSI とノイズ。間の幅が SNR。10秒〜5分、一時停止、CSV 保存
- **周りの電波**: 約8秒ごとにスキャンし、2.4 / 5 / 6 GHz の各チャンネルの電波を「山」で描画。重なり（混み具合）も一覧に
- **受信の内側**: 電波が混んだ場所で受信機の中で何が起きているかを 4 段で見せる
  1. **アンテナに届く電力** — 自分の親機・混信（周波数が重なる電波の合計）・雑音を並べ、使える余裕 SINR を出す
  2. **順番待ち (CSMA/CA)** — 同じチャンネルで「送り終わるまで待つ」相手の台数を実測から数え、送信の順番と衝突をスローモーションで再現
  3. **復調（星座図）** — 送信レートから今の変調（例: 1024-QAM・2 ストリーム）を逆算し、実測 SINR ぶんの雑音で揺らした受信点と読み間違いを描く
  4. **速度** — 規格上の最高 / いまのレート / SINR で出せる目安 / 順番待ち後の実効の目安
  - 「試しに雑音を足す」スライダーで、混んだ場所を疑似体験できる

**Web デモ**: https://denpa-scope.vercel.app （作り物のデータで動きます。実測は下の手順で Mac 上で）

## 使い方

```bash
npm start        # http://localhost:5730 （初回は Swift ヘルパーを自動ビルド）
npm run demo     # 作り物のデータで動かす（画面に「デモデータ」と出ます）
npm test
```

依存パッケージはありません（Node と Xcode Command Line Tools の swiftc だけ）。

## しくみ

```
helper/wifi-probe.swift  CoreWLAN で RSSI/ノイズ/速度/チャンネルを 0.1 秒ごと＋スキャン結果を JSON Lines で出力
server.js                ヘルパーを起動し、Server-Sent Events でブラウザへ中継。web/ を配信
web/lib/*.js             純粋関数 = テスト対象
                           wifi / series / needle / spectrum  チャンネル↔周波数、統計、針の物理、山の形
                           receiver  周りの電波を「自分・順番待ち・混信・無関係」に分類、SINR
                           mcs       MCS と速度の規格表、送信レートから変調を逆算
                           qam       星座図のシミュレーションと理論誤り率
                           csma      CSMA/CA のスロット単位シミュレーター
web/app.js               描画と配線（Canvas 2D）
web/inside.js            「受信の内側」パネルの描画
```

## 制限

- macOS は位置情報の許可がないプロセスに **SSID / BSSID を渡しません**。名前は「取得不可」になりますが、チャンネル・幅・強さは実測です
- スキャン結果には OS のキャッシュが混ざるため、近くにもう無い電波が少しのあいだ残ることがあります
- 「順番待ち」と「混信」の線引きは 802.11 の受信感度（同じ主チャンネルは -82 dBm、エネルギー検出は -62 dBm）に沿った目安です。相手が実際にどれだけ送っているかは Mac からは見えないので、取り分は「全員がずっと送りたいとき」の最悪値です
- 自分の親機は「同じ主チャンネル・同じ幅で RSSI が最も近い電波 ± 3 dB」と推定しています（同じ親機の別 SSID をまとめるため）
- 星座図は実測そのものではなく、実測 SINR から作った再現です（Mac は受信した生の記号を外に出しません）
- 2.4 GHz の 40 MHz 幅は上下どちらに伸ばしているか取得できないため、端に寄らない側と仮定して描いています
